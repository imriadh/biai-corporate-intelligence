# BIAI Corporate Intelligence — Submission Note (half page)

**What I built.** A corporate sales intelligence CRM that turns BIAI's 25 messy fictional sample leads into a clear, queryable pipeline. Deployed on Cloudflare Workers + D1 (persistent SQLite) + Hono + React/Vite, with a public SaaS landing page at `/` and the app at `/app`. Six screens: Executive Dashboard (KPIs, pipeline chart, stage breakdown, overdue + data-quality summaries), Leads Pipeline (search/filter/sort with overdue/missing/duplicate flags), Lead Details + AI Email Assistant, Data Quality Center (exact + potential duplicate detection with merge review, missing contacts, date-order validation), AI Sales Analyst (natural-language questions), and a CSV import/export flow. Login is credential-based (JWT in an httpOnly cookie). All 25 leads are loaded into D1 — none discarded — and the audit catches every deliberate mistake: 1 exact duplicate (L01/L23), 1 potential duplicate (L02/L03), 2 missing-contact records (L06, L24), 1 date-order violation (L25), 9 overdue follow-ups.

**AI tools used and how.** I used an AI coding assistant (Claude) for scaffolding, the CSV parser, prompts and the test suite; I designed the data model, duplicate/date/overdue rules and the two-layer query strategy myself. The app's AI runs on **Cloudflare Workers AI** (Llama 3.1 8B, free tier) — chosen because the supplied Z.ai key authenticates but has no account balance, and Groq's `gsk_` key was auto-revoked. The provider is env-configurable (Z.ai / Groq / OpenRouter as fallbacks). Two real AI capabilities: (1) follow-up email drafting — sends the lead's real notes/stage/contact to the model with a strict no-fabrication system prompt, returns a properly-structured email (greeting → body → next-step → "Best regards" on its own line), with a one-click "Send via Gmail" button that opens Gmail compose pre-filled; (2) natural-language pipeline queries — common questions answered deterministically with exact math (no AI, no hallucination), flexible questions go to the AI which returns a structured query spec executed locally against real D1 data (the model never invents records or totals). Plus an AI weekly chase plan that prioritizes overdue + upcoming leads. Email generation ~1-2s; deterministic queries ~0.3s.

**How data validation works.** A single TypeScript pipeline imports the CSV (or reads from D1), normalizes additively (company comparison keys, email casing, phone digits, ISO date parsing with impossible-date rejection), detects exact + potential duplicates, validates date order (follow-up vs last contact, respecting terminal stages), and computes overdue from the reference date (2026-11-01 per the brief). Nothing is auto-corrected or auto-deleted; the Data Quality Center shows both raw and normalized values with a manual merge-review workflow. The pipeline is cross-checked against an independent Python audit (25/25 checks match) and covered by 37 unit tests.

**What does not work yet.** No persistence for the duplicate-merge decision (it's a UI review note, not written to D1). Password hashing is SHA-256 (acceptable for a single demo credential over HTTPS; upgrade to bcrypt before real multi-user). The Z.ai key has no balance so Workers AI is the active provider. Reference date is fixed at 2026-11-01 per the brief (the code supports live "today" mode via an env var).

**What I'd fix next.** Persist merge decisions to an `audit_log` table; add the AI weekly email digest via Cloudflare Cron Triggers; upgrade to bcrypt + add a signup flow; swap the fixed reference date for today in a live deployment; and add a mobile kanban view of the pipeline.
