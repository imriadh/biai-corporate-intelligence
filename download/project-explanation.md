# BIAI Corporate Intelligence — Project Explanation (half page)

**What was built.** A lightweight corporate sales-intelligence CRM on Next.js 16 + TypeScript + Tailwind + shadcn/ui that turns BIAI's 25 messy fictional sample leads into a clear, queryable pipeline. Five screens: an Executive Dashboard (KPIs, pipeline chart, overdue + data-quality summaries, recently updated leads), a filterable/sortable Leads Pipeline table, a Lead Details view with an AI follow-up-email assistant, a Data Quality Center (duplicates with merge review, missing contacts, date validation), and an AI Sales Analyst that answers natural-language questions about the pipeline. All 25 records are loaded, none discarded; raw values are preserved alongside normalized ones.

**AI tools used and how.** I used an AI coding assistant (Claude) to scaffold components, write the CSV parser, draft prompts and generate the test suite; I personally designed the data model, the duplicate/date/overdue rules and the two-layer query strategy. The app itself uses a configurable multi-provider AI backend (Z.ai LLM SDK as the reliable default, Groq / OpenRouter / NVIDIA as OpenAI-compatible fallbacks, all server-side env-configured).

**How AI is integrated.** Two real capabilities. (1) Follow-up email drafting: the lead's actual company, contact, stage, deal value, dates and notes are sent to the model with a strict no-fabrication system prompt; missing fields are explicitly listed so they are never invented. (2) Natural-language pipeline queries: common questions (overdue, totals by stage, missing contacts, counts, priority) are answered **deterministically** with exact calculations — no AI, no hallucination. Flexible questions go to the AI, which returns a **structured query spec** (filter/sort/aggregate/limit) that the app executes locally against the real data. The model never returns records or totals; it only returns a query plan.

**How data validation works.** A single TypeScript pipeline (`src/lib/data/pipeline.ts`) imports the CSV, normalizes additively (company comparison keys, email casing, phone digits, ISO date parsing with impossible-date rejection), detects exact and potential duplicates, validates date order (follow-up vs last contact, respecting terminal stages), and computes overdue from the fixed reference date 2026-11-01. Nothing is auto-corrected or auto-deleted; the Data Quality Center shows both raw and normalized values and offers a manual merge-review workflow. The pipeline is cross-checked against an independent Python audit (25/25 checks match) and covered by 37 unit tests.

**What does not work yet.** No persistence (edits not wired — optional Priority 1); the duplicate merge is a review note only (not persisted); CSV export not yet exposed in the UI; the supplied `gsk_*` Groq key was rejected (HTTP 403) so the app runs on the built-in Z.ai LLM.

**What I'd improve next.** Add Prisma + SQLite for persistence + edit/merge logging; expose CSV export of cleaned data; add the optional AI weekly "chase-first" summary; swap the fixed reference date for the current date in a live deployment; and add auth only if multi-user is needed.
